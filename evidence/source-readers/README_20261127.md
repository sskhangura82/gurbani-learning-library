## What the checks establish

- Complete owning source groups and every original line are compared against
  independently hash-pinned data at both ends of their page spans: SGGS ZKH
  (Ang 1–2), SKD (465–466), TNM (929–938), FD3 (1429–1430); Dasam KKH
  (page 1), 4TJ (738–748), BTE (1427–1428). A page route renders every owning
  group in manifest order. Deep-linking focuses a line without clipping the
  other groups. FD3's source-reported ALAM attribution stays qualified as
  digital-source metadata.
- Page entry, previous/next, boundaries, reload, Back/Forward and exact line
  links preserve the requested page and ownership. Malformed, duplicate,
  unknown and mismatched routes refuse all original text; Go can recover.
- Saving is explicit and uses the collection-and-edition-specific namespace.
  Valid synthetic records require explicit Resume and source verification.
  Corrupt, stale and wrong-page records remain byte-for-byte unchanged.
  Other collection keys and unrelated synthetic records are untouched.
- A new Save supersedes both success and failure of an older delayed Resume.
  These cases first evict the saved chunk from the runtime cache, hold its
  response, save a new verified place, and then release the old response.
  The new record remains resumable and the view does not navigate backward.
- Same-length valid-JSON mutations of the manifest or original-text chunk
  refuse all text. Mutated reader bundles fail the unchanged HTML integrity
  pin before any source-data request. Unbundled runtime source modules are
  denied by the fixture server.
- Both readers remain public and fit a 320 CSS-pixel viewport at default and
  largest Gurmukhi sizes. The six final screenshots were visually inspected:
  headings, controls, original text and per-line page metadata remain legible
  without horizontal overflow.

## Environment, reproduction and limits

Observed environment: macOS, Node `v22.15.0`, Playwright `1.62.1`, Chrome
`158.0.8127.37`. Each scenario uses a fresh headless context; browser contexts
and the loopback server close after the run. Service workers are blocked in
this fixture to isolate source-reader delivery and state. The parent
integration separately checks actual service-worker behavior.

From a complete checkout with Playwright and Chrome available:

```sh
GLP_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
GLP_CHROMIUM_EXECUTABLE=/absolute/path/to/chrome \
GLP_SOURCE_READER_OUTPUT=/absolute/path/to/new-evidence-directory \
node tests/source-reader-browser.mjs
```

The retained Mac snapshot is `/tmp/glp-source-reader-browser-cwp927xr`.
Its reports are under `evidence/source-readers/browser/` with the same run
directory names used here. This run used the existing Playwright installation
at `/tmp/glp-final-browser-y5b4ko9n/node_modules/playwright/index.mjs` and
Chrome at `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`.

Only public imported original text and synthetic saved places were used.
The fixture server rejects private-library paths before reading them. No
owner PIN, private payload, personal reflection, existing browser profile,
remote push or deployment was involved.

This verifies the named digital source and its complete reported groups,
not independent printed-edition collation or disputed historical authorship.
The browser exercises representative page spans and 29 public files; the
separate core contracts cover all 155 imported chunks. These are desktop
Chrome checks at a narrow viewport, not physical iPhone, Safari, VoiceOver
or independent Claude review.
