# Official Daily Hukamnama importer: builder evidence

This is branch work for an isolated development candidate. It does not sign,
publish, deploy, authorize content, or satisfy independent/qualified review.

## Reproduce

From the repository root:

```sh
python3 tests/hukamnama-ingest.py
python3 tools/ingest-hukamnama.py --date 2026-11-27 --out /tmp/NEW-UNUSED-STAGING-DIRECTORY
```

Omit `--date` to select today's **Asia/Kolkata** calendar date. A future date is
refused before any request. An explicitly requested past date remains historical;
it never substitutes for today. The output parent must already exist and the
output path must not exist. There is no force/overwrite option.

The successful real-source capture for this candidate is in
`capture-2026-11-27/`. `INGESTOR_CAPTURE_20261127_ATTEMPT1.txt` records the actual
first command result. `INGESTOR_TESTS_20261126.txt` records the synthetic tests.
No physical-device testing is asserted.

`tests/hukamnama-signing.mjs` additionally seals the actual original-only capture
with a fresh in-memory P-256 key and independently decodes the event and full
source. It never reads or writes the development private-key file. Its first run
is retained in `SIGNING_TESTS_20261126_ATTEMPT1.txt`: nine cases passed and two
metadata-tamper cases correctly exposed acceptance gaps in the signer. Rehashed
receipts could change their starting Ang or displayed time without matching the
source/event. The builder added those exact comparisons; the separate second-run
log records the recheck. The actual captured source, receipt and event already
had matching metadata and were not changed to make these tests pass.

## Output and signing boundary

The new directory contains:

- `manifest.json`: exact-byte digests and relative paths for each artifact.
- `sources/<textSha256>.json`: immutable original-only source package.
- `events/YYYY-MM-DD.payload.json`: unsigned dated event, with all lessons null.
- `receipts/YYYY-MM-DD.original.json`: original-only source/date observations,
  exact witness-file digests, boundaries, provenance and limitations.

The source package's identity hashes every original occurrence joined by one
ASCII space. Repeated identical lines receive distinct occurrence suffixes inside
the immutable unit. No row, Ang-only, first-line or fuzzy identity is used.
JSON uses UTF-8, sorted keys, two-space indentation and one final newline.
Source packages contain no retrieval timestamp. Receipt and event timestamps
are identical, UTC, and end in `Z`.

The receipt has a stable `original` object containing only `date`, `ang`,
`hukamnama_time`, `gheading1`, `gheading2`, `ghukamnama`, `gfooter1`, `gfooter2`.
An archive-only historical record has a null displayed time. No time-zone offset
is invented for the publisher's displayed clock time.

A separate signing tool must check the receipt, event and exact source bytes
before sealing. Staging is never deployment. The importer never reads a private
key. Source or verification failures produce no final staging directory. A disk
write failure removes temporary artifacts while leaving existing records alone.

## Transport and source behavior

The importer uses fixed HTTPS source URLs and bounded responses, refuses all
redirects and unexpected encodings, and uses strict UTF-8. Current-date imports
require both the official portal and the observed official archive query to
agree. Past dates use the explicit archive date response. HTTP 200 by itself is
insufficient; the archive can return `supported: false` with no original body.

Official source: <https://hs.sgpc.net/>

Official archive: <https://hs.sgpc.net/archiveView.php>

Observed read-only archive query:
`POST https://hs.sgpc.net/hssearchhukmanamaTestCalender.php`, form field
`selected_date=YYYY-MM-DD`, as used by the official archive's own script.
This is not claimed to be a documented external integration API.

Earlier read-only transport inspection found `X-Frame-Options: SAMEORIGIN`,
`Content-Security-Policy: frame-ancestors 'self'`, and no
`Access-Control-Allow-Origin` in a response requested with the test site's
Origin. The app therefore uses its own signed dated artifacts and keeps a normal
official-source link available. This code does not add an iframe or CORS proxy.

The old `hukamnamapdf/hukamnama.pdf` URL returned a September reading despite
HTTP 200 during research. The current portal generates its PDF in the browser.
Neither legacy PDF URL nor search indexing is used for a daily selection.

## Integrity limitations, deliberately visible

- Full sequence uniqueness is checked among candidates beginning on the
  official starting Ang, with the necessary adjacent pages and boundaries.
  Global uniqueness across all 1,430 Angs is not asserted.
- The witness window is bounded to 16 forward Angs, plus preceding boundary
  context only when needed. Unsupported structural endings or missing boundary
  evidence refuse the import; no guessed completion is emitted.
- Boundary classification is conservative. New legitimate structures require
  a reviewed parser change. No Unicode, spelling or punctuation normalization
  is performed. A disagreement is a refusal to investigate, not an automatic
  change to either source.
- A source beginning with no available preceding original entry is refused by
  this version. There is no invented preceding digest.
- Page frontmatter's author or raag is not used to classify every unit on a
  page. A single Ang can contain more than one author's compositions.
- Portal and archive are one publisher. Open Granth derives from Shabad OS
  SSA2, which cites SGPC's Shabadaarth. These are not independent historical
  transmission lines or substitutes for qualified/printed-page review.

## Rights and provenance

Every real import rechecks four exact pinned notice/provenance bytes. Their URLs
and SHA256s are recorded in the original-only receipt. Open Granth's licence
explicitly scopes MIT to code and tooling and excludes the corpus from that MIT
grant. Its NOTICE and provenance document identify the original text's source.
The pinned upstream Shabad OS README separately identifies original Gurbani and
Panthic texts as public domain and calls for preservation of their integrity.

The upstream notice is pinned to archived repository commit
`918c1d42d02e385e7ed48ef44994c75a2cb50293`, not claimed to be the exact notice
bundled with npm `5.0.0-next.0`: its registry gitHead returned 404 during research.
No permission to reproduce modern commentary, translations, audio or PDF layouts
is established by these notices. Such fields are discarded. Explanations stay
null, with the official page available by normal external link.

## Shared strict JSON parser and stage-contract integration

`hukamnama/json.mjs` exports `parseStrictJSON(text)` without dependencies, imports
or dynamic code. A bounded structural scan checks every decoded object key
before final native JSON parsing, so duplicate keys (including escaped-equivalent
spellings) cannot discard hidden values. Native parsing still supplies string,
number and final-value semantics. Ordinary JSON whitespace and key ordering are
accepted; Unicode keys are not normalized. Limits are 40 nested containers and
2,621,440 UTF-16 code units; transport callers retain their separate raw-byte
limits. Invalid input raises data-free errors rather than quoting field values.

`tests/hukamnama-json.mjs` has 16 passing cases, recorded in
`STRICT_JSON_TESTS_20261126_ATTEMPT1.txt`. The importer itself already rejects
duplicate JSON keys through Python's object-pairs hook.

After the separate strict stage-contract validator was integrated by the other
builder, signing attempt three preserved four assertion failures caused by
changed refusal wording: those inputs were correctly refused earlier by the new
validator. Only invariant-specific error-message expectations were adjusted.
Five additional tests demonstrate that duplicate values cannot hide in the
payload, escaped-equivalent source keys, receipt, reader envelope, or even a
correctly signed decoded payload. `SIGNING_TESTS_20261126_ATTEMPT4.txt` records all
16 signing checks passing. All earlier logs remain. The real source capture and
its signed event were not modified by this work.
