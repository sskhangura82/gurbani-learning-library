## 4. One data architecture
Separate:
- `scripture_occurrence`: canonical local identity + corpus/version + upstream ID aliases, exact original Unicode and SHA-256, sequence, Ang and cross-Ang span, heading/rahao/verse status, shabad/unit ID, author and raag.
- `shabad`: stable ID, exact ordered occurrence list and digest, start/end, cross-edition map; not an Ang alone, not first line alone. New edition mismatch requires adjudication, stable old identifiers and migration.
- `hukamnama_event`: venue + ritual (official morning selection) + Amritsar Gregorian date + source-printed calendar fields; selected shabad version and selected boundaries; immutable evidence URLs, fetched timestamp and evidence digest; status pending/confirmed/conflict/unavailable; append-only correction log. Multiple dates can refer to same lesson; never conflate daily audio with a separate Paath.
- `lesson_revision`: shabad/unit ID + exact source hash + language + content layer + contributor, citations, review state, revision history, qualified approval where applicable. Reuse only on exact compatible source/scope, invalidate/re-review after changes.
- `concept_edge`: source passage + relevant term/sense + target Gurbani/other tradition/study + similarity AND difference + context/references/review; no keyword-only doctrinal equivalence.
- `recording`: original reciter/identity evidence, custodian, exact edition/recitation tradition, kind (Mukhwak, Katha, Santhiya, Paath, Kirtan), canonical coverage and exceptions, media checksum/version, rights receipt ID, scoped playback/hosting/caching/timing permissions, verified URLs and duration. Separate date-specific Mukhwak events.
- `alignment`: recording checksum + exact text version + occurrence/token IDs + integer start/end milliseconds + alignment granularity, confidence, human reviewer and known deviations. Preserve originals; no silent editing or shared timing across recordings.
- `learning_local`: bookmarks, notes, journal (optionally keyed to event and passage), preference and position, versioned lossless export/import. No outbound transfer. Keep reading without audio or learning storage.

## 5. Daily ingest and editorial publication
Use date in Asia/Kolkata; explicit YYYY-MM-DD in requests, not browser locale or assumed UTC. In California, India may already have next date even before morning Mukhwak publication; show pending, not yesterday relabeled. Distinguish event date, fetched time, local user date and last-known confirmed event. Verify source venue/morning/date, compare full selected ordered text to pinned corpus incl headings/rahao/end, document differences. Secondary witness corroborates but cannot overrule official source or guarantee independent lineage. Reject malformed, truncated, ambiguous, mismatched, stale or conflicting results; do not fall back to random Gurbani. Surface last confirmed date explicitly when available; do not withdraw already verified historical events because today's fetch fails.

Design build-time adapter/controlled publisher: bounded requests, timeout/backoff, evidence hashes, idempotent validation, staged review and signed/approved manifest; static same-origin dated event files and separately updated current-date pointer. Existing PWA uses hash-pinned release cache with ignoreSearch matching, so never key daily events by query string alone or allow a stale cache to masquerade as current. Keep shell, archive content and permitted optional audio caches separate. Validate manifest and actual dates on startup and refresh. Atomic publication; no overwriting source data or auto-deploy of drafts; no daily full-app rebuild or service worker replacement. Historical date navigation can use exact stored events; uncovered days remain unavailable. Do not add outbound browser requests for user's search, journal or preferences.

Teaching workflow: 2–3 minute bilingual simple (central teaching + reflection), 10–15 minute detailed (every source occurrence including Rahao, vocabulary, grammar, literal/context distinction, author/raag, cross-Gurbani), 20–45 minute optional deep (complete passage study, relevant comparative religion/psychology, evidence and limits). Reading time is an intended range, not a measured guarantee. Keep reflections separate from source. Family/newcomer explanations remain authentic; no medical or psychological treatment guarantees. Rahao guides interpretation when present; do not reduce the Shabad to a self-esteem slogan. Approve each layer separately; if only original is confirmed, publish original and already approved lessons, explicitly mark additional education pending. Draft lesson version stays private/nonpublishing until approved. No live generative answers.
