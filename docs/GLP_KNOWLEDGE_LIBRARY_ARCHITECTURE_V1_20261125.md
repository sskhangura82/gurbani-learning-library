# GLP-001 — Knowledge Library architecture v1

Date: 2026-11-25. **Nonpublishing development proposal and bounded executable pilot.**
The owner's direction is one canonical Gurbani knowledge library, not a folder hierarchy or a collection of separate readers. Preserve the existing public site, reader experience, storage keys and source IDs.

## Decisions

- Public readers currently use static, hash-pinned assets and local learning. Start with versioned JSON packages and generated indexes, with optional SQLite/relational editorial tooling later. Do not add a graph database, live AI, backend account or paid service now.
- Model scripture **collection**, source edition, contributor, Raag, composition, passage and original occurrence separately. SGGS, Dasam Bani, Vaaran Bhai Gurdas Ji and Bhai Nand Lal Ji retain distinct provenance and status. Composition collections may reference multiple passage records; do not re-copy original text into course or topic files.
- Logical passage identity and edition-bound text occurrence identity are separate. A repeated identical string is not automatically the same occurrence. Preserve exact Unicode and order; no search normalization in the source. Use explicit edition/occurrence crosswalks, source checksums, corpus-specific boundaries and reviewed migrations. The three IDs in this pilot are provisional local IDs, not certified universal corpus IDs.
- Index by Ang, author, Raag, composition, exact words/phrases, curated concepts, human experiences and interdisciplinary studies. A single concept can appear in multiple categories. Search normalization and Roman aliases only operate on retrieval copies. Exact text, contextual vocabulary, curated aliases and editorial connections are visibly distinct result reasons. Never infer doctrinal equivalence from co-occurrence.
- Vocabulary requires lemma/sense ID, actual attested form, occurrence and passage context, grammatical/etymological evidence and review status. Unwritten senses must stay missing. Tap-word UI cannot silently replace the original spelling with a dictionary headword.
- Concept identity is separate from versioned educational lesson. Each lesson revision references exact passage versions. A current pointer may select a new independently reviewed revision; historical courses, source events and editorial receipts keep their previous revision reference. Re-review when source meaning, edition or boundaries change. Audio and daily events reference the same source identity; timing maps reference specific recording + text edition. Private learning and position are a separate local layer.
- Distinguish structural facts from editorial relationships. Typed directional relations require valid endpoints; interpretive links require reason, source context and review status. Psychology/philosophy links require named reference, meaningful similarity AND difference, and evidence limitations; no medical or theological equivalence. Gurmat remains the primary frame. Original Gurbani, translation, teaching, scholarly and clinical evidence are distinct.

## Schema / future relational tables

Collections, editions, contributors, raags, compositions, passages, occurrences, passage_occurrences (ordered), word_lemmas, attested_tokens, contextual_senses, concepts, concept_categories, lessons, lesson_revisions, citations, relationship_edges, recordings, recording_alignments, hukamnama_events, courses, course_steps. Maintain an append-only review/evidence ledger and a separate local-learning migration registry. Build deterministic manifests and generated indexes; public runtime can consume partitioned packages.

## Pilot contents and exact limits

`knowledge/pilot.json` holds 31 typed nodes, 26 relationships, 19 original source occurrences, three complete Saloks at three Angs, three contributor records, six dictionary headwords with contextual senses, six concepts (only two three-depth lessons), two comparative study references and one two-step draft pathway. The other four concepts are placeholders with no teaching. The exact original is drawn from pinned Open Granth/Shabad OS commit 34d2a7cab032c8ea24d21ff20f64653bd03766f4. Both SriGranth page witnesses for Angs 466 and 470 and the indexed SriGranth results for the two Kabir Salok 7 verses corroborate all 19 source rows by visual comparison. This is digital comparison, not independent lineage or print/qualified collation; no modern third-party translation is imported. The two conceptual lessons are compact EN/PA examples, not full 20–45 minute lessons or every-pankti explanation.

The standalone development route `knowledge/index.html` uses the pure graph validation and search in `core.mjs`, verifies fixture bytes against a pinned SHA-256, displays complete selected Saloks, provides context-specific word buttons, explicit three-level topic teaching and linked contributor/composition/concept/study/course navigation. The hash detects changes to fixture bytes under an unchanged trusted app; it does not protect against replacement of the whole app. Search handles exact phrases, first letters at a row start, Ang in Arabic/Gurmukhi digits, curated English/Punjabi/Roman aliases and a selected author filter. It does not implement arbitrary spelling correction, full SGGS index, semantic natural-language understanding or a full dictionary. No verified deep-link adapter into existing readers yet; this route opens its own complete selected passage and maintains in-session back navigation. No personal data stored or transmitted. No audio, permissions, offline release, full-text directory, actual iPhone/iPad/Safari/VoiceOver acceptance or public navigation added.
